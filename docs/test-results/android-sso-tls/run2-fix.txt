Android sign-in on Android 9: the fix in CI (run 2)
===================================================
GitHub Actions run 39080198652 (workflow_dispatch, android.yml), commit ceeebec, 2026-10-17/18
https://github.com/Techprosoftware707/0trust-chat/actions/runs/39080198652
Fix: CertificateVerifier checks certificates that name no OCSP responder against their CRL only
(soft failure when the CRL cannot be fetched); the network security config allows plain http to
the CAs' CRL hosts only. Excerpts copied from the job logs (timestamps removed).

Job results:
  success  Build, test, package (unit tests incl. RevocationCheckTest, lint, debug/release APKs, AAB)
  success  Screenshots
  success  Instrumented tests (emulator), API 35: 19 passed, 4 skipped (the tests that need a test server)
  success  Installs, starts and passes the SDK TLS tests on Android 9 (API 28): 12/12
  success  Installs, starts and passes the SDK TLS tests on Android 8.0 (API 26): 12/12
  success  App against a real Lumen server (emulator, Android 8.0): 42/42 (sign-in, encrypted chat, sign-out)
  failure  App against a real Lumen server (emulator, Android 9): 25 PASS, 6 FAIL; phase a (sign-in) passed;
           phase b stopped at "accepting the invitation joins the chat" (60 s)
  failure  App against a real Lumen server (emulator), API 35: 36 PASS, 4 FAIL; phases a and b passed; phase c
           stopped at "Settings -> Sign out" (60 s)
Both e2e failures: the Rust SDK's connection to the CI-hosted server stalled for about a minute
after the session was restored (API 35 logcat: the logout POST and the pending sync got no answer;
the sync failed with reqwest TimedOut after 60 s, while the platform HTTP client's whoami still
got 200). The private test CA means no revocation check, so the changed code is not on that path,
and the same steps passed on API 26 in this run and on API 35 in run 1. Run 3 waits up to 180 s
for those two steps and keeps the server's logs on failure.
