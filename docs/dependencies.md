## Method

Every entry below comes from a file or artifact that was read on the date above.
Where a license comes from general knowledge instead, it is marked as such.

- The `/venv` inside the built `lumen/portal:1.0.0` image holds exactly those 25 packages plus `pip` 26.2.1 (MIT).
- Every installed npm package matches its lockfile version and license field. Every npm package declares a license.

## 6. License obligations and notes

> Not legal advice. This section records facts from the inventory and points out
> questions. Decisions on how a license applies belong with counsel.

### 6.1 Synapse (AGPL-3.0-or-later OR Element commercial license)

- **License.** The pinned artifact declares `AGPL-3.0-or-later OR LicenseRef-Element-Commercial`. Lumen uses it under the AGPL option; no commercial license with Element is recorded in this repository.
- **When source must be offered.** AGPL-3.0 §13 applies to a **modified** version that users interact with over a network. It requires offering those users the Corresponding Source of that modified version. Running a modified Synapse as a network service therefore triggers the source-offer obligation.
- **How Lumen runs it.** Lumen runs the **unmodified upstream image**:
  - it is pulled by digest from `ghcr.io/element-hq/synapse`;
  - the compose service has an `image:` line and no `build:` step;
  - no Synapse files are patched.
- **Upstream source for the pinned version.** This is the link ADR 0001 D2 asks this inventory to provide. It is derived from the image labels and was not fetched during this inventory:
  - Repository: https://github.com/element-hq/synapse
  - Tag: `v1.163.0`
  - Commit: `193cf9466fbfbe334700c541dc1442f135179aaf`
- **The module.** Lumen loads its own out-of-tree module (`services/synapse-module`) into the Synapse process through the documented module API.
  - **Whether a module loaded this way is a derivative work** (that is, whether Synapse plus module counts as a "modified version") **is a legal question for counsel**.
  - Publishing the module's source under an AGPL-compatible license avoids having to settle it: anyone using the service could get the module source either way. The source is in this repository.
  - However, the module directory **carries no license declaration** and the repository has **no LICENSE file** (see 6.2). The avoidance argument depends on the repository actually being published under a stated license.
- **Distribution.** Lumen does not redistribute Synapse binaries. Operators pull the upstream image themselves.

### 6.2 Lumen's own license

- **Where a license is declared.** AGPL-3.0-or-later appears in two places:
  - `services/chat/package.json` (`"license": "AGPL-3.0-or-later"`)
  - the portal image label (`org.opencontainers.image.licenses`)
- **What is missing.**
  - The repository has **no LICENSE or COPYING file** (only the third-party license files under `design/`).
  - No source file carries an SPDX header.
  - `services/synapse-module` declares nothing.
- **Effect if Lumen is AGPL.** If the intent is AGPL-3.0-or-later, adding the license text at the repository root, and making the module's license explicit, would make that declaration effective and consistent.
- **Obligations on others.** Under that license, third parties who modify Lumen and run it as a network service would have §13 obligations themselves.

### 6.3 LGPL components

**psycopg 3.3.6 and psycopg-binary 3.3.6 (LGPL-3.0-only)**

- Both are used unmodified, as separately installed and replaceable Python packages.
- LGPL obligations mostly attach to **distribution**: providing the license text, allowing users to replace the library, and making the library's source available.
- The portal image is built **on the operator's host** from PyPI wheels, so Lumen itself does not currently distribute these wheels.
- If a prebuilt portal image is ever published, it should carry the license texts and source pointers. That would also cover the native libraries bundled in `psycopg-binary` (libpq, OpenSSL, Kerberos, OpenLDAP, Cyrus SASL, PCRE, libselinux, libcrypt, keyutils; licenses *to verify*), and the Debian base packages of the `python` image.

**In the upstream Synapse image:** `psycopg2` ("LGPL with exceptions") and `ldap3` ("LGPL v3"). Distribution of these is upstream's.

**Stray, not shipped:** `jwcrypto` (LGPL-3.0-or-later) is only in the local venv (section 2.3).

### 6.5 Permissive licenses in the shipped chat bundle (Apache-2.0, MIT, ISC)

- **What is bundled.** The browser bundle includes minified code from 20 runtime packages plus the crypto WASM.
- **Notices required.** The licenses require keeping copyright and permission notices in copies. Apache-2.0 §4 also requires giving recipients a copy of the license and preserving any `NOTICE` file. Serving JS and WASM to browsers is commonly treated as distribution.
- **NOTICE files.** None of the six Apache-2.0 production packages ships a `NOTICE` file (checked by file listing). `requests` (server-side, portal) does.
- **Current state (fixed).** `build.license` is enabled in `services/chat/vite.config.ts`; the build emits `dist/licenses/third-party.md` with the license text of every bundled npm package (20 entries in the 1.0.0 build), linked from the chat app's Settings → About → "Open-source licences".
- **Crypto WASM contents.** `@matrix-org/matrix-sdk-crypto-wasm` is compiled from many Rust crates (vodozemac, matrix-sdk-crypto and their dependencies). The npm package ships only its own Apache-2.0 `LICENSE`, so the licenses of those crates are *to verify* upstream.

### 6.6 Fonts (SIL OFL 1.1)

- **What OFL allows.** The fonts may be used, embedded and redistributed with software. They must not be sold on their own.
- **What OFL requires.** Each copy must carry the copyright notice and the license. A separate text file is acceptable.
- **No Reserved Font Names** are declared.
- **Portal:** satisfied (the license files are published as static files).
- **Chat:** satisfied — the OFL texts ship in `dist/licenses/` (see 4.1).

### 6.7 Icons (ISC, plus MIT for Feather-derived icons)

- **Portal:** `LICENSE-lucide.txt` (ISC and Feather MIT text) is published alongside the vendored SVGs, and each SVG keeps its `@license` header.
- **Chat:** the icons come from `lucide-react` and are bundled without its `LICENSE` (same gap as 6.5).
