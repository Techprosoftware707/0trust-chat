# Nexus integrations: Gmail, GoHighLevel, Slack and the unified inbox

`apps.integrations` (portal) and the **Inbox** and **Integrations** areas (chat SPA). The API
contract and the service functions other teams call are in
[ARCHITECTURE.md](ARCHITECTURE.md#13-integrations-and-the-unified-inbox-team-b2) (section 13);
variables are in [CONFIG.md](CONFIG.md#integrations-and-the-unified-inbox-team-b2); decisions in
[IMPLEMENTATION-NOTES.md](IMPLEMENTATION-NOTES.md#team-b2-integrations-and-the-unified-inbox) ("Team B2").

**Testing status, honestly:** no real Google, Slack or HighLevel credentials exist for this
work. Every automated test and the browser smoke run against local **fake providers**
(`apps/integrations/mock/providers.py`) that answer the documented URLs and shapes. Nothing in
this build has been tested against the live services. See [What is tested](#what-is-tested-and-what-is-not).

## 1. What each integration does

| | Gmail | GoHighLevel | Slack |
|---|---|---|---|
| Owner | personal: the person who connects (their own mailbox) | workspace: an owner/admin connects | workspace: an owner/admin connects |
| Who sees synced items | only the mailbox owner (not even admins) | everyone with record access | everyone with record access |
| Auth | OAuth 2.0 web-server flow, offline access, **PKCE S256** + client secret | Marketplace app OAuth (Sub-Account token) **or** a Private Integration Token | OAuth v2 (bot token), client secret |
| Scopes | `gmail.readonly`, `gmail.compose` | see §4 | `channels:read`, `channels:history`, `chat:write`, `users:read` (+ `groups:read`, `groups:history` only on admin opt-in) |
| Sync | thread/message metadata + snippets; incremental through `history.list` | pipelines, opportunities, conversations (+ missed calls), tags, custom fields | Events API for selected channels; one back-fill page per newly selected channel |
| On demand | message bodies (sanitized), attachments (proxied), live search with Gmail `q` | contact search, contact detail with tasks and appointments, conversation messages | permalinks |
| Writes (always after confirmation) | send a reviewed reply draft | create/update a contact; start a workflow (production only, admin opt-in) | post to a selected channel (thread replies) |
| Not supported | push notifications (Pub/Sub) — polling instead | replying to conversations (link out) | private channels without opt-in, DMs, Enterprise Grid org installs |

Every synced item is **external and untrusted**: it is labelled with its source, never shown
as a native chat, never treated as instructions (the AI tools mark it too), and never shown as
"sent" unless the provider confirmed it.

## 2. Setup (administrators)

All client IDs go in `lumen.conf`; all secrets are secret files set with
`sudo ./lumenctl set-secret <name>` (hidden input), then `sudo ./lumenctl apply`. The token
encryption key `nexus_integrations_key` is generated by the installer. The Integrations page
shows, per provider, which settings are present (names only), the exact redirect URI and
webhook URL to register, and these steps.

URLs below use `https://<domain>` = `LUMEN_PUBLIC_BASE_URL` (the portal, e.g. `https://example.com`).

### Google (Gmail)

1. Google Cloud Console → create or pick a project → **APIs & Services → Library → Gmail API → Enable**.
2. **Google Auth Platform** (OAuth consent screen): set the app name, support email and
   authorized domain; **Audience**: External (or Internal for one Google Workspace
   organisation); **Data access**: add `https://www.googleapis.com/auth/gmail.readonly` and
   `https://www.googleapis.com/auth/gmail.compose`.
3. **Clients → Create client → Web application**; authorized redirect URI:
   `https://<domain>/integrations/oauth/google/callback` (exact match, including scheme and
   trailing path).
4. `NEXUS_GOOGLE_CLIENT_ID=<client id>` in lumen.conf; `sudo ./lumenctl set-secret nexus_google_client_secret`.
5. **Verification:** both Gmail scopes are *restricted*. Until Google verifies the app, only
   test users you add can connect, and with publishing status "Testing" refresh tokens expire
   after 7 days (people then see "Needs reconnecting"). Production use by customers needs
   Google's OAuth verification and, because restricted-scope data is processed on a server, a
   security assessment. Plan for this before launch.

### GoHighLevel

Either (A) a Marketplace app (OAuth) or (B) a Private Integration Token. Both connect **one
sub-account (location)** per Nexus workspace.

**A. Marketplace app.** HighLevel developer portal → create an app with Target user
**Sub-account**; **Advanced Settings → Auth**: add the scopes from §4, the redirect URL
`https://<domain>/integrations/oauth/crm-connector/callback`, and generate a client key
pair; **Webhooks**: webhook URL `https://<domain>/integrations/webhooks/gohighlevel`
(subscribe to InboundMessage, OutboundMessage, Contact\*, Opportunity\*, AppUninstall). Then
`NEXUS_GHL_CLIENT_ID=<client id>` (and optionally `NEXUS_GHL_APP_ID=<app id>` plus the
`oauth.write` scope, so that **Disconnect** can call the documented uninstall API) and
`sudo ./lumenctl set-secret nexus_ghl_client_secret`. The person connecting chooses the
sub-account on HighLevel's page; agency-wide (Company) installs are refused with a clear
message.

**B. Private Integration Token.** In the sub-account: **Settings → Private Integrations →
create**, select the scopes from §4, copy the token; in Nexus: Integrations → GoHighLevel →
"Use a private integration token" → paste the token and the location ID. It is stored
encrypted and never shown again. It does not refresh; HighLevel recommends rotating it every
90 days: **Replace token** on the connection stores the new one and keeps the connection and
its synced data. Webhooks are not available with B.

### Slack

1. https://api.slack.com/apps → **Create New App** (from scratch) in your Slack workspace.
2. **OAuth & Permissions**: redirect URL `https://<domain>/integrations/oauth/slack/callback`;
   **Bot Token Scopes**: `channels:read`, `channels:history`, `chat:write`, `users:read`
   (add `groups:read`, `groups:history` only if admins should be able to opt in to private
   channels). Token rotation is optional; when it is on, Nexus refreshes the 12-hour tokens.
   Do **not** enable PKCE for this app (that makes it a public client; Nexus is a
   confidential server-side client).
3. **Event Subscriptions**: enable; request URL `https://<domain>/integrations/webhooks/slack/events`
   (Slack sends a `url_verification` challenge; Nexus answers it only with a valid
   signature); **Subscribe to bot events**: `message.channels` (and `message.groups` if
   private channels are opted in). `app_uninstalled` and `tokens_revoked` are delivered
   without extra scopes and move the connection to "Needs reconnecting".
4. **Basic Information**: copy the client ID, client secret and **signing secret**:
   `NEXUS_SLACK_CLIENT_ID=<id>`; `sudo ./lumenctl set-secret nexus_slack_client_secret` and
   `sudo ./lumenctl set-secret nexus_slack_signing_secret`.
5. After connecting in Nexus: invite the app to each channel in Slack (`/invite @app`), then
   select the channels on the Integrations page. Only selected channels are stored.

Rate limits to know: as an **internal** (single-workspace) app, `conversations.history` is
Tier 3. Apps that are *commercially distributed but not in the Slack Marketplace* and created
after 2025-05-29 get 1 request per minute and at most 15 messages per page; Nexus only uses
history for a one-page back-fill and relies on the Events API.

### Redirect URIs and webhook URLs (summary)

| Provider | Redirect URI | Webhook / events URL |
|---|---|---|
| Google | `https://<domain>/integrations/oauth/google/callback` | — (no push; polling) |
| HighLevel | `https://<domain>/integrations/oauth/crm-connector/callback` | `https://<domain>/integrations/webhooks/gohighlevel` |
| Slack | `https://<domain>/integrations/oauth/slack/callback` | `https://<domain>/integrations/webhooks/slack/events` |

The HighLevel path avoids the provider's brand name on purpose (HighLevel's guidelines ask
white-label installs not to show it).

## 3. How connecting works (security)

1. The SPA calls `POST /api/v1/workspaces/<id>/integrations/connections/oauth-start`
   (bearer token). The server checks the person may connect this provider (Gmail: anyone but
   read-only people; HighLevel and Slack: owners/admins), creates an `OAuthState` (random
   nonce stored **hashed**, PKCE verifier stored **encrypted**, expires in 10 minutes) and
   returns a portal URL carrying a **signed** state (`django.core.signing`, salt
   `nexus.integrations.oauth-state`, max age 10 minutes) naming the nonce, provider,
   workspace and person.
2. `GET /integrations/oauth/begin` needs the **portal session of the same person**; it puts a
   random binding into that session (its hash on the state row) and redirects to the
   provider with `state` (and `code_challenge`/S256 for Google).
3. The provider redirects to `/integrations/oauth/<provider>/callback`. The callback refuses
   anything but: a valid signature within its age, an existing unexpired nonce, the same
   provider, workspace and person, **the same browser session** (login-CSRF protection),
   and a state never used before (marked used atomically: replays fail). The person must
   still be allowed to connect in that workspace. Only then is the code exchanged (client
   secret + PKCE verifier), the account identified and the tokens stored.
4. Errors return to the app as `#/integrations/error/<code>`; provider messages are never
   echoed. Rejected states are recorded as security events.

HighLevel documents neither a `state` round trip nor PKCE for its authorization page. Nexus
sends `state` and verifies it when it comes back; if it does not come back, the callback is
accepted only for the **single** pending, unexpired HighLevel flow bound to the same browser
session and person (and nothing else). This is untested against the live service.

**Tokens** are encrypted with AES-256-GCM (`apps/integrations/crypto.py`): key from
`NEXUS_INTEGRATIONS_KEY_FILE` (env only in development), a random 96-bit nonce per value, and
associated data binding each ciphertext to its connection and field (a copied value does not
decrypt elsewhere). Several keys may be listed (first encrypts, all decrypt) for rotation;
`manage.py nexus_integrations_rekey` re-encrypts every credential with the first key, so the
old one can be removed (CONFIG.md, "Rotating the integrations key").
Tokens are never logged, serialized, returned or audited; tests assert this with `caplog`.

**Refresh.** Access tokens are refreshed 90 seconds before expiry, or once after a 401, under
a row lock (Slack and HighLevel refresh tokens are single-use: two workers never spend the
same one; if another worker refreshed meanwhile, its token is used). A refused refresh
(`invalid_grant`, revoked app, expired PIT) or a second 401 moves the connection to
**needs_reauth** with a **Reconnect** action; Reconnect re-runs the flow for the same account
(Google gets `login_hint`) and refuses a different account.

**Provider errors** (`apps/integrations/http.py`): idempotent requests are retried on 5xx and
network errors with exponential backoff and jitter (≈1 s, 2 s, 4 s); 429 (and Google's
`rateLimitExceeded`/`userRateLimitExceeded` 403s, Slack's `ratelimited`) honour
`Retry-After` inline only up to 5 seconds, otherwise the sync is rescheduled after the wait;
`dailyLimitExceeded` waits an hour. Sends, posts and other non-idempotent requests are
**never retried automatically**. Sync failures back off (2, 4, 8 … 60 minutes); three in a row
mark the connection "Error" with the last safe message and a **Retry now** button. Missing
scopes are reported as such.

## 4. Scopes (least privilege) and why

| Provider | Scope | Why |
|---|---|---|
| Gmail | `gmail.readonly` (restricted) | thread/message metadata, `history.list`, search with `q` (not available with `gmail.metadata`), bodies and attachments on demand |
| Gmail | `gmail.compose` (restricted) | `drafts.create/update/delete/send` for reviewed replies; Gmail can be connected without it (read only) |
| HighLevel | `contacts.readonly` | contact search/lookup/detail, a contact's tasks and appointments |
| HighLevel | `contacts.write` | create/update a contact, add to a workflow (each confirmed) |
| HighLevel | `opportunities.readonly` | opportunities and pipelines |
| HighLevel | `conversations.readonly`, `conversations/message.readonly` | conversations and their messages (read-only) |
| HighLevel | `locations.readonly` | the sub-account's name (and verifying a pasted token) |
| HighLevel | `locations/tags.readonly`, `locations/customFields.readonly` | tags and custom fields |
| HighLevel | `workflows.readonly` | list workflows |
| HighLevel | `oauth.write` (only with `NEXUS_GHL_APP_ID`) | uninstall the app on disconnect |
| Slack | `channels:read` | list public channels for selection |
| Slack | `channels:history` | messages of selected channels (events and back-fill) |
| Slack | `chat:write` | post to a selected channel after confirmation |
| Slack | `users:read` | names instead of member IDs |
| Slack | `groups:read`, `groups:history` (opt-in) | private channels the app was invited to |

Granted scopes are recorded per connection; features whose scope was not granted are
disabled and say why (e.g. "Drafting replies wasn't allowed when Gmail was connected").

## 5. What is stored, for how long

| Data | Stored | Retention |
|---|---|---|
| Tokens | encrypted, one row per connection | deleted immediately on disconnect |
| Gmail | per thread: subject, participants (names/addresses), snippet, label IDs, dates, message count; per message: from/to/cc/reply-to, subject, date, snippet, label IDs, `Message-ID`/`References` (for threading replies), attachment names/types/sizes once a message was opened | `NEXUS_GMAIL_RETENTION_DAYS` (90) after the last activity; initial sync covers 30 days |
| Gmail bodies, attachments | **never stored**; fetched on demand, bodies sanitized (allowlist, no scripts/styles/forms, **no images**, links `noopener noreferrer`), shown as text by default or in a sandboxed `default-src 'none'` iframe; attachments proxied with `Content-Disposition: attachment`, `nosniff` | — |
| Reply drafts | recipients, subject and text while it is a draft (so the reviewed text is exactly what is sent) | text cleared when sent or discarded |
| Slack | messages of **selected** channels only: text (≤4000 chars), author ID/name, time, thread, mentions | `NEXUS_SLACK_RETENTION_DAYS` (30); removing a channel deletes its messages |
| HighLevel | conversations (name, last message text, unread), missed calls; mirrors of opportunities, pipelines, tags, custom fields, and contacts that were opened/linked | `NEXUS_GHL_RETENTION_DAYS` (90) |
| Webhook deliveries | provider, event ID, type, outcome (no payload) | `RETENTION_WEBHOOK_DAYS` (90) |
| Links to records | the inbox item ↔ record edge; linking to a contact or deal adds an **untrusted** timeline entry (subject/snippet) | until unlinked (the entry is removed with the link); timeline entries are business records |

The worker job `integrations.retention` (hourly) applies these; `integrations.sync` (every
minute) runs due syncs (`NEXUS_INTEGRATIONS_SYNC_SECONDS`, default 300).

## 6. Ownership and disconnect

* Gmail connections belong to the person who connected; only they read the mail. Owners
  and admins see that a mailbox is connected (status only) and can disconnect it (offboarding).
* GoHighLevel and Slack connections belong to the workspace; owners/admins connect, change
  settings (Slack channels, private-channel opt-in, HighLevel workflow triggers) and
  disconnect. The connecting admin is recorded as the owner. Anyone may set their own Slack
  member ID (for "Mentions").
* **Disconnect** revokes at the provider where the API supports it (Google revoke endpoint;
  Slack `auth.revoke`; HighLevel uninstall API when `NEXUS_GHL_APP_ID` and `oauth.write` are
  configured), deletes the tokens immediately, and by default deletes everything synced
  through the connection. "Keep synced data" hides it (disconnected) and the retention job
  deletes it after 30 days. When revocation isn't possible or wasn't confirmed, the result
  says what to do at the provider (e.g. delete the Private Integration Token).

## 7. Webhooks

| | Slack Events API | HighLevel |
|---|---|---|
| Verification | `v0` HMAC-SHA256 of `v0:<timestamp>:<raw body>` with the signing secret, constant-time compare | Ed25519 signature (`X-GHL-Signature`, base64) over the raw body with HighLevel's published public key (`NEXUS_GHL_WEBHOOK_PUBLIC_KEY`, default = the key in HighLevel's guide). The legacy RSA `X-WH-Signature` is deprecated (2026-09-01) and not accepted |
| Replay | timestamp more than 5 minutes off → 401 | `timestamp` older than 24 hours → 400; every replay inside that window is a duplicate |
| Dedup | `event_id` (unique per provider) | `webhookId`, else SHA-256 of the signed body |
| Answer | 200 quickly; processing errors → 500 and the claim is released so Slack's retry is processed | same (HighLevel retries up to 12 times) |
| Invalid / unconfigured | 401 / 404, security event | 401 / 404, security event |

## 8. The unified inbox

The SPA merges, in the browser: **native rooms** from the Matrix client (previews decrypted
on the device; nothing about them is sent to the server except, if the person chooses, a
room ID to link or mute), **synced items** from `GET …/integrations/inbox`, **workspace
notifications** from the automation app, and **meeting follow-ups** (calendar events that
ended in the last 7 days and are still "scheduled"). Merge rules live in
`services/chat/src/workspace/integrations/merge.ts` (unit-tested):

* badges: Encrypted chat (native), Gmail · Synced email, Slack · External message,
  HighLevel · Imported record, External notification (missed calls), Workspace;
  mock items carry "Mock provider (development)";
* a synced item is never presented as native, whatever its payload says;
* unread is per person; priority, assignment, labels and done exist for synced items only
  (filters on them hide chats and say so); personal mail can only be assigned to its owner;
* notification grouping collapses a Slack channel or a notification type into one row;
  mute hides a group (Slack channel, email sender, HighLevel conversation, chat room,
  notification type) per person;
* linked records (contact, deal, task, or any registered record type) open in a side panel
  without leaving the inbox; suggestions by email/phone are never applied automatically;
* replies: Gmail through a draft and the confirmation dialog; Slack thread replies through
  the confirmation dialog; HighLevel replies are not supported here (link out to HighLevel);
* `#/inbox/<inbox_item_id>` opens an item (links from the AI assistant); **Ask AI** on an item
  passes `context.inbox_item_id`.

## 9. Mock mode (development and test only)

`NEXUS_INTEGRATIONS_MOCK=1` (default in `dev/nexus/env.sh`) routes every provider call to the
in-process fake providers and replaces the providers' consent screens with
`/integrations/mock/<provider>/authorize`. It is **refused when `NEXUS_ENVIRONMENT=production`**
(the setting is ignored, a system-check warning is printed, the renderer rejects it, and the
Integrations page says so). The whole OAuth machinery (signed state, session binding, PKCE,
single use, token encryption, refresh) still runs. Every surface it affects says
"Mock provider (development)": the Integrations page (banner, cards, connections), the consent
page, the inbox (banner, item badges, detail), and confirmation dialogs. Mock connections and
everything synced through them are flagged `is_mock`/`is_demo`. Mock data is synthetic
(example.com/.org/.net people, subjects marked "(mock data)"). Workflow triggers never run in
mock mode.
