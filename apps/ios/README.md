# Lumen Secure for iPhone and iPad

Native SwiftUI app (iOS/iPadOS 17+) on the Matrix Rust SDK
(`matrix-rust-components-swift`, pinned to **26.10.02**), as decided in
[ADR 0003](../../docs/adr/0003-client-apps.md). It implements the server
contract in [docs/apps/integration.md](../../docs/apps/integration.md).
Release, signing, push and App Store steps: [docs/apps/release-ios.md](../../docs/apps/release-ios.md).
Feature status: [FEATURES.md](FEATURES.md).

## Layout

| Path | What it is |
|---|---|
| `project.yml` | XcodeGen spec: targets `Lumen` (app), `LumenNSE` (notification service extension), `LumenTests`, `LumenUITests`; Swift packages |
| `Lumen.xcodeproj` | Generated from `project.yml` (`xcodegen generate`). CI regenerates it; don't edit it by hand |
| `LumenCore/` | Swift package with the platform-independent logic: URL policy, discovery and `io.lumen.app` parsing, deep links and the SSO nonce, delivery state, notification preview policy, widget-bridge filtering, app-lock timer, device API, log redaction. Foundation only; builds and tests on macOS, iOS and Linux |
| `Lumen/Matrix/` | The Matrix layer on the Rust SDK: session and sync, room list, timeline, encryption and verification, pusher, call-widget driver |
| `Lumen/Shared/` | Shared by the app and the NSE: configuration, store paths, Keychain account store, client factory, notification mapping |
| `Lumen/Platform/` | iOS integrations: `ASWebAuthenticationSession`, `LAContext`, notifications, CallKit + PushKit + audio session, the WKWebView call-widget host |
| `Lumen/Features/` | SwiftUI screens |
| `Lumen/DesignSystem/` | `LumenTokens.swift` (generated by `design/tools/gen_tokens.py`, don't edit), theme glue, the vector brand mark |
| `Lumen/Resources/` | Asset catalog (icon, launch logo, colours), `PrivacyInfo.xcprivacy`, `Localizable.strings` |
| `Lumen/Supporting/` | `Info.plist`, entitlements |
| `LumenNSE/` | Notification service extension: decrypts `event_id_only` pushes, applies the preview policy, hands rings to CallKit |
| `scripts/` | `ci-build.sh` (CI), `copy-call-widget.sh` (build phase), `gen-app-icon.py`, `linux-check.sh` |

## Build and run

Requirements: a Mac with Xcode 26 (iOS 26 SDK; deployment target stays iOS
17), [XcodeGen](https://github.com/yonaskolb/XcodeGen) 2.46.0 or later.

```bash
brew install xcodegen
cd apps/ios
xcodegen generate
open Lumen.xcodeproj          # run the "Lumen" scheme on a simulator
```

The first build downloads the Rust SDK's `MatrixSDKFFI.xcframework`
(about 280 MB) through Swift Package Manager; its SHA-256 is pinned in the
package's `Package.swift`.

To bundle the call widget, build it first (`npm run build:widget` in
`services/chat`, producing `services/chat/dist-widget/`). The
`Bundle the call widget` build phase copies it into the app as `CallWidget/`.
Without it the app uses the server's `call_widget_url` and says so in
Settings → About.

Command line, exactly as CI does it (simulator build, tests on an iPhone and
an iPad simulator, unsigned archive; outputs in `apps/ios/build/`):

```bash
bash apps/ios/scripts/ci-build.sh           # from the repository root
```

Running on a device needs your own team and identifiers:

```bash
xcodebuild -project apps/ios/Lumen.xcodeproj -scheme Lumen \
  -destination 'generic/platform=iOS' -allowProvisioningUpdates \
  DEVELOPMENT_TEAM=ABCDE12345 LUMEN_BUNDLE_ID=com.example.chat build
```

## Configuration (build settings, no source changes)

| Build setting | Default | Effect |
|---|---|---|
| `LUMEN_DEFAULT_SERVER` | empty | Server name pre-filled in the sign-in screen (a name like `example.com`, not a URL). Empty: the user types one |
| `LUMEN_BUNDLE_ID` | `io.lumen.secure` | Bundle ID, URL scheme and SSO redirect (`<id>:/sso-callback`); the NSE is `<id>.LumenNSE` |
| `LUMEN_APP_GROUP` | `group.$(LUMEN_BUNDLE_ID)` | App group shared with the NSE (stores and preferences) |
| `LUMEN_DISPLAY_NAME` | `Lumen` | Home-screen name |
| `LUMEN_PUSH_APP_ID` | `$(LUMEN_BUNDLE_ID).ios` | Pusher `app_id`; must match `PUSH_IOS_APP_ID` on the server |
| `LUMEN_ENTITLEMENTS_FILE` + `LUMEN_ASSOCIATED_DOMAIN` | `Lumen.entitlements`, empty | Set `LumenWithLinks.entitlements` and `app.example.com` to enable universal links |
| `DEVELOPMENT_TEAM` | empty | Your Apple team ID (never committed) |
| `MARKETING_VERSION`, `CURRENT_PROJECT_VERSION` | `1.0.0`, `1` | Set by CI from the tag and run number |

Everything else comes from the server at runtime (integration.md §2):
`/.well-known/matrix/client` and its `io.lumen.app` block, `/versions`,
`/login`. URLs must be `https` (plain `http` only to loopback hosts in Debug
builds); certificate validation is never disabled, and CI fails if
`disableSslVerification` appears in the iOS sources.

The server needs native (simplified) sliding sync, which Synapse provides
from 1.114; discovery checks `org.matrix.simplified_msc3575` and explains
when it is missing.

## How it works, briefly

- **Sign-in**: discovery → `Client.startSsoLogin(redirectUrl:idpId:)` →
  `ASWebAuthenticationSession` (ephemeral) → callback checked against a
  per-attempt nonce (`?n=`) → `SsoHandler.finish(callbackUrl:)`. The session
  is stored in the Keychain (`AfterFirstUnlockThisDeviceOnly`, shared access
  group); the SQLite stores live in the app-group container under
  `completeUntilFirstUserAuthentication`, encrypted with a random 32-byte
  passphrase that is itself kept in the Keychain.
- **Sync**: `SyncService` (with offline mode) and `RoomListService`; the
  connection banner comes from the real sync state.
- **Timeline**: `Room.timeline()` diffs are applied in order on the main
  actor; delivery ticks come only from the SDK send state ("Sending" for a
  local echo, "Sent" after the server's event ID, "Read" after someone
  else's receipt).
- **Push**: only when the server announces `push_gateway_url`; the pusher is
  `event_id_only` with `mutable-content`. The NSE opens the same store
  (cross-process lock), decrypts with `NotificationClient` and shows a
  content-free notification unless the user chose otherwise. Without a push
  gateway the app says so and uses short background refreshes.
- **Calls**: CallKit + the Lumen call widget in a WKWebView, connected to
  `WidgetDriver`/`WidgetDriverHandle` through the bridge in integration.md
  §6.2. The encryption label in the call screen is the widget's own `e2ee`
  state.

## What can be checked without a Mac

```bash
bash apps/ios/scripts/linux-check.sh   # needs a Swift 6.x Linux toolchain on PATH
```

It builds `LumenCore` in Swift 6 mode and runs its tests (including
`apps/shared/test-vectors`), then type-checks `Lumen/Matrix` and the
SDK-facing `Lumen/Shared` files against the real Swift bindings and C
headers of the pinned SDK release (warnings are errors). SwiftUI, UIKit,
CallKit, PushKit, WebKit, Keychain and the NSE need Xcode.

## Tests

- `LumenTests` (logic tests, no host app): all `LumenCore` tests, the shared
  test vectors (`apps/shared/test-vectors`, bundled as a resource), and
  app-level tests of the SDK mappings (VoIP ring payload, session mapping,
  widget URL accepted by the SDK, call capabilities).
- `LumenUITests`: launch → server picker. With `LUMEN_UITEST_SERVER` set
  (passed to the runner as `TEST_RUNNER_LUMEN_UITEST_SERVER` by
  `ci-build.sh`), it looks the server up and expects the SSO button. No
  account is used.
