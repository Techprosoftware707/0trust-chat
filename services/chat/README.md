# Lumen web chat client

The browser chat app for Lumen Secure: a standard [Matrix](https://matrix.org) client
(React 19 + TypeScript + Vite) with end-to-end encryption by default. It is a static
site: Caddy serves `dist/` plus a `config.json` rendered by the installer.

## Architecture

```
src/
  main.tsx, App.tsx        boot: config → SSO token exchange / stored session → client start
  config.ts                /config.json loading + validation (brand, homeserver, SSO, links, voip)
  lib/                     pure helpers: markdown (safe subset), formatting, routes, theme, prefs,
                           session-crypto (WebCrypto pickle key), session-store, idb, tab-lock
  matrix/                  SDK integration: client lifecycle, login/discovery, UIA (password + SSO
                           fallback), secret-storage callbacks, security flows, media
                           (encrypted attachments), rooms/DMs, timeline building, notifications, calls
  hooks/                   React hooks over SDK events (rooms, sync state, trust, presence, security)
  components/              UI (sidebar, room, timeline, composer, dialogs, settings, calls)
  styles/app.css           component styles on top of design/tokens.css
```

### Cryptography (none implemented here)

* **Messages**: matrix-js-sdk 44 with **Rust crypto only** (`initRustCrypto`, vodozemac via
  `@matrix-org/matrix-sdk-crypto-wasm`). Olm/Megolm, cross-signing, SAS verification, secret
  storage and key backup are all the SDK's.
* **Attachments**: the spec'd AES-CTR + SHA-256 scheme from `matrix-encrypt-attachment`
  (WebCrypto). In encrypted rooms files are encrypted before upload; the key/IV/hash travel
  inside the encrypted event. Downloads use authenticated media (`/_matrix/client/v1/media/…`
  with an `Authorization` header), the hash is verified and the file decrypted in the browser,
  and previews use short-lived `blob:` URLs that are revoked on unmount.
* **Session at rest** (Element's "pickle key" pattern): a random AES-GCM key is generated by
  WebCrypto as *non-extractable* and stored as a `CryptoKey` in IndexedDB (`lumen-session`).
  The access token and a random `storagePassword` are sealed with it (user/device bound as
  AAD). `localStorage["lumen-session"]` only holds user ID, device ID and homeserver URL.
* **Crypto store**: IndexedDB `lumen-crypto::matrix-sdk-crypto(-meta)`, encrypted by the SDK
  with `storagePassword`. Sync cache: IndexedDB `matrix-js-sdk:lumen-sync` (server-visible data
  only; encrypted events stay ciphertext). A Web Lock keeps a second tab from opening the same
  crypto store concurrently.
* **Sign-out** calls `/logout`, then deletes the pickle key and sealed secrets *first* (so the
  crypto store, encrypted with the now-unrecoverable `storagePassword`, is unreadable at once),
  then `clearStores` + the databases, and reloads the page so nothing decrypted stays in memory.
  The Rust crypto store can stay open for a while after the client stops; if its deletion is
  still pending it completes at the next start (any leftover databases are deleted on boot when
  there is no session).
* The recovery key is generated by the SDK, shown once (copy/download), must be re-entered to
  confirm, is only kept in memory for the duration of an operation and is never logged.
* Logging: the SDK (and Rust crypto) log level is `error` in production builds. The app never
  logs message contents, keys, tokens or recovery keys.

### Content Security Policy

Works under `default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self'; …`:
no inline scripts (the pre-paint theme script is `/theme-init.js`), no runtime `<style>`
injection (all CSS is one hashed file; React `style` props only via CSSOM), no `eval`, the
crypto WASM is a hashed `.wasm` asset, no `data:` assets (inlining disabled), no source maps.
Message bodies are rendered as React elements from a tiny parser (bold, italic, inline code,
code blocks, http(s) links) — never `dangerouslySetInnerHTML`; received HTML is ignored.

### Runtime config and branding

`/config.json` (installer output) supplies the brand names, homeserver, SSO provider, links and
`voip_enabled`. `/brand/theme.css` (operator overrides, loaded last; a 404 is harmless) and
`/brand/logo.svg` (falls back to the bundled `branding/logo.svg`) come from the operator's
branding directory. Theme choice is shared with the website via `localStorage["lumen-theme"]`.

## Features

Sign-in with SSO (`/login/sso/redirect/<idp>` → `?loginToken` removed from the URL immediately →
`m.login.token`), other homeservers via `.well-known` discovery (SSO and/or password), deep links
`#/dm/@user:server` (existing DM opens; new contacts need a confirmation click). Room list with
DMs/groups, filter and chips, unread/highlight counts from notification counts, invites. New DM
(user directory search) and new group (encrypted by default; disabled toggle with explanation
when the server forces encryption). Timeline with back-pagination, day separators, grouping,
replies, reactions, edits, deletion, typing, delivery state (sending → sent → seen by N from read
receipts; failed with retry/cancel), unable-to-decrypt hints. Encrypted attachments with size
limit from `/media/config` and progress. Per-room encryption badge, per-message shields from
`getEncryptionInfoForEvent`, member list with trust state, SAS emoji verification (users in a
DM, own devices), incoming request toasts, identity-change banners (pin / withdraw / verify).
Secure backup set-up, verify-with-recovery-key (restores the backup), change key, restore, reset.
Sessions (rename, verify, sign out others with UIA by password or SSO popup). Desktop
notifications (permission only from the settings toggle; push-rule driven; previews off by
default). On-device search (+ optional server search for unencrypted rooms). Presence, typing,
connection banner (sync state + `navigator.onLine`). Settings: profile, appearance, notifications,
security & privacy (read receipts / typing toggles), sessions, about. Optional legacy 1:1
voice/video calls when `voip_enabled` (media protection shown only from `getStats()`).

## Development

```sh
npm ci
npm run devserver:up      # disposable Synapse "lumen-chatdev-synapse" on 127.0.0.1:28008 (Docker)
npm run dev               # http://127.0.0.1:5173 — dev/config.json points at the dev homeserver
```

Create users with `tests/chat/lib/synapse.mjs` (`registerUser`, shared-secret admin API) or
any Matrix client. `npm run devserver:down` removes the container; `node
../../tests/chat/devserver.mjs reset` also deletes its data.

## SDK notes

* matrix-js-sdk 44 sends events to a room it doesn't know about **without encryption**
  (`encryptEventIfNeeded` returns early). The app only sends to joined rooms it has synced, and
  the composer refuses otherwise. Its own encryption decisions (header badge, attachment
  encryption) use the SDK's rule: encrypted if the room has `m.room.encryption` *or* the crypto
  layer says so.
* With the IndexedDB sync store the SDK reports `Prepared` from its cache before the first live
  sync, so state derived from account data (secret storage) is re-read after the live sync.
* `getEncryptionInfoForEvent` uses non-strict shields: messages from unverified users with
  cross-signed devices show no warning; the app adds "verified" only when you verified the sender.
* Synapse can force encryption for all new rooms (`encryption_enabled_by_default_for_room_type`,
  advertised as `io.element.e2ee_forced.*`); the new-group dialog then disables the toggle.
* `clearStores()` can block for ~25 s because the Rust store's IndexedDB connection outlives
  `stopClient()`; hence the shred-first sign-out above.

## Known limitations

* No QR-code verification (emoji/SAS only); no threads, spaces, polls, stickers sending, voice
  messages, rich-text editor, mentions/pills, room settings beyond enabling encryption, or
  ignoring users.
* Received HTML (`formatted_body`) is not rendered; the plain `body` is shown with our safe
  markdown subset.
* Search is over messages loaded and decrypted on this device (encrypted search can't be done
  server-side); there is no persistent local search index.
* Notifications only appear while the tab is open (no service-worker/web-push).
* Group calls (MatrixRTC/Element Call) are not supported; 1:1 calls use legacy Matrix VoIP and
  need a TURN server for most real networks.
* One account per browser profile.
