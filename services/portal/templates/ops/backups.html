Controlled recovery

  1. Run “Verify latest restore” — it restores into an isolated, temporary database and checks integrity without touching production.
  2. To restore production, run sudo ./restore.sh <archive> on the server. It verifies checksums, asks for typed confirmation, takes a safety backup, and explains which encryption data can and cannot be recovered.
  3. See docs/operations/disaster-recovery.md for server replacement and DNS changes.
